### 发给朋友玩（绿色版）

**不要直接把整个文件夹压缩发过去。** 两个问题：

1. `node_modules/` 里装着 Electron 运行时（268MB），再加上存档、截图、日志，
   压出来又大又杂；
2. 更要命的是**对方没装 Node/Electron 就跑不起来**（双击 `index.html` 也不行 ——
   ES module 从 `file://` 加载会被浏览器拦掉）。

正确顺序是先出一个**正式构建**，再用它做绿色版：

```bash
npm i -D electron-builder        # 只有第一次需要
npm run dist:dir                 # → dist/win-unpacked/Colony Frontier.exe（带图标与版本信息）

node tools/make-portable.mjs --zip --split   # → 绿色版文件夹 + zip + 60MB 分卷
```

产物（`dist/`）：

| 文件 | 大小 | 用途 |
|---|---|---|
| `win-unpacked/` | 279MB | **正式构建**：exe 里有产品名/公司/版本号与游戏图标，`resources/app/` 是游戏本体。**Steam depot 传的就是这个目录** |
| `开拓者-殖民地-绿色版.zip` | 113MB | 发给朋友（网盘/U盘/QQ） |
| `game.zip.part01/02` + `合并并解压.cmd` | 60+53MB | 微信 100MB 上限时用 |

绿色版里附 `启动游戏.cmd`（纯 ASCII，避免代码页问题）与 `怎么玩.txt`（按键表、
开局三步、存档位置、出错怎么反馈）。朋友解压后双击 exe 即可，不需要装任何东西。

> 两个坑：
> 1. **`.cmd` 里不要写中文** —— 批处理受控制台代码页影响，中文路径在部分机器上会乱码，
>    表现是「双击没反应」。启动脚本与合并脚本一律 ASCII + 通配符。
> 2. 朋友那边**一台电脑只能跑一份**（单实例，见下）—— 正常双击就行，不需要任何设置。

### 单实例：一台电脑只跑一份

正式行为是**单实例**：第二次双击不会开出第二个窗口，而是把已经在运行的那份**拉到前台**
（`second-instance` 事件里 `restore() + focus()`）。必须这样，因为两份进程会同时写
`%APPDATA%\<应用名>\saves\*.json`（自动存档互相覆盖），还会抢音频设备与手柄输入。

只有**开发/测试**需要多开（比如一边开着 `npm start`、一边验绿色版），用环境变量：

```powershell
$env:FRONTIER_MULTI=1      # 允许同时开多份；额外的实例自动换独立存档目录（…-2 / …-3）
$env:FRONTIER_SHARE_SAVES=1  # 配合上面那个：故意让额外实例共用同一批存档（有覆盖风险）
```

多开时 `app:info` IPC 会带上 `extraInstance`（0 = 主实例）与 `shareSaves`，
主菜单据此弹一条「多开模式」提示说明这一份的存档在哪，免得玩家以为存档丢了。

### 这样能在 Steam 上架吗？

**能，而且不需要换引擎。** Steam 不要求游戏用某个引擎，它只要求你给一个可执行文件 +
depot 内容。SteamDB 的「Electron 容器」技术页上现在挂着 **3000 多个产品**
（Cookie Clicker、Crosshair X、Sunshine Heavy Industries、Choice of Robots…），
Phaser 官方也有一篇 [用 Electron 把网页游戏发到 Steam 的教程](https://phaser.io/news/2025/03/publishing-web-games-on-steam-with-electron)。

本仓库的打包链路已经是正式形态：

| 项 | 状态 |
|---|---|
| exe 图标 / 产品名 / 公司 / 版本号 | ✅ electron-builder 写入（`assets/icon.ico`） |
| 构建产物结构 | ✅ `Colony Frontier.exe` + `resources/app/`（≈ 任何 Electron 游戏装完的样子） |
| Steamworks 成就 / 统计 / 云存档 | ✅ 代码已接（`electron/steam.cjs` + `src/core/steamClient.js`，没 Steam 时静默降级） |
| 手柄 / Steam Deck 输入 | ✅ 手柄是「插上即用」的一套动作映射 |
| 中文 UI | ✅ 全中文，商店页再补英文本地化即可 |
| **待办（都在 Steamworks 后台或商店侧）** | AppID、12 条成就与 3 条统计的录入、depot 上传、商店素材（截图/胶囊图/预告片）、Auto-Cloud 路径 |

**什么时候才真的该换引擎？**

| 需求 | 说明 |
|---|---|
| 上主机（Switch / PS / Xbox） | ❌ Electron 没有官方主机支持，这是唯一硬伤；Godot 可以走第三方移植 |
| 3D / 复杂物理 | 现在的 2D Canvas 管线够用，做 3D 就得换 |
| 美术/策划协作、编辑器驱动的内容量 | 引擎的可视化编辑器更省事（Godot 4 是最省迁移成本的选项） |
| 发行商/平台要求 | 极少数发行商会指定引擎，一般不会 |

换句话说：**这游戏的问题不是「用没用引擎」，而是「上架前的那堆非代码工作」**
（素材、商店页、Steamworks 录入）。详见 `steam/STEAM-CHECKLIST.md`。

### 验证

```bash
node tools/verify.mjs         # 不需要 Electron 的部分
node tools/verify.mjs --all   # 再加浏览器端 / 核心循环 / 设置与模式 / 手柄 / 手柄映射
```

汇总表里的项数是**自动**从各个子测试的输出里抓的，不用手改。
`--all` 需要 Electron 与正在运行的 `npm run dev`。

> 单独重跑某一项：`node tools/inputBuffer.mjs`、`node tools/smoke.mjs`；
> 挂在 Electron 下跑的：`electron tools/settings.cjs`（设置与两种模式 + 副本流程）、
> `electron tools/gamepadMap.cjs`、`electron tools/gamepad.cjs`。
>
> **「用了但没导入」用 `node tools/freescan.mjs` 扫**。`checkimports.mjs` 查的是
> 「导入的名字在目标模块里存在吗」，反过来「用到的名字导入了吗」它不管 ——
> 玩家在建造面板撞到的 `TILE is not defined` 就属于后者，
> 语法检查、import 检查、面板能否打开的断言全都是绿的。
>
> **「运行出错」怎么查**：报错通知里现在带**源码位置**（`src/xxx.js:123`），
> 并且每条错误都留在 `window.__frontierErrors` 里（含堆栈前几帧）。
> 暂停菜单 →【错误日志】能直接看、能一键复制。
> `tools/liveprobe.mjs` 可以连到正在运行的游戏上抓控制台错误并执行页面脚本
> （用法：`electron . --remote-debugging-port=9333` 启动，然后
> `node tools/liveprobe.mjs --script tools/probe-sweep.js`）——
> 玩家那台机器上的问题，用这个不用重装环境就能复现。
>
> 静态检查还有两个补充：`node tools/freescan.mjs`（用了但没导入的名字）、
> `node tools/localscan.mjs`（拼错的局部名）。它们都挡不住「删了声明却留着使用」
> 这种错，那一类靠跑起来抓（`smoke.mjs` 的 120 秒模拟就抓到过一次
> `nest is not defined`）。
>
> **视觉问题用截图看**：`npm run shots` 会把主菜单、设置、降落页、科技树、城镇、
> 行星地图、虫巢与副本地图截到 `tools/shots/`。层级错位、面板被盖住这类问题
> 断言抓不到，只能靠眼睛（「设置打不开」就是这么发现的）。
>
> 想直接看玩家那台机器上的画面（比如他截图里的控制台报错），
> `tools/capture-window.ps1 -Pid_ <electron 的 PID>` 可以把正在运行的游戏窗口抓成 PNG。
>
> 地图尺寸相关的性能用这两个基准脚本量（改 `WORLD_TILES` / `FLOW_CELL` 前先跑一遍）：
> `node tools/mapbench.mjs`、`node tools/flowbench.mjs`。
> 改了样式表里的尺寸单位，跑一下 `node tools/scale-css.mjs` 保持缩放一致。

## 两种游戏模式

主菜单顶部可以切换，切换后按「开始」进的就是对应模式。

| | ❖ 开拓模式 | ⛨ 纯塔防模式 |
|---|---|---|
| 角色操控 | 有（四选一，各有专属武器/建筑/实验池） | **没有** —— 基地就是全部 |
| 世界 | 整颗星球：几十个虫巢、遗迹、vault、载具探索 | **一片阵地**（半径 900px 的建造区） |
| 怪从哪来 | 吸引装置从巢穴牵引，按牵引强度组波 | 波次系统从阵地外生成，逐波变强 |
| 材料来源 | 地图采集 + 击杀掉落 | **只有击杀掉落**（按稀有度分档） |
| 建造范围 | 基地 + 420px（科技可扩） | 整片阵地 |
| 落点选择 | 三级难度，保证有一个最安全的一级 | 无（只有一片阵地） |
| 科技 / 实验科技 / 城镇 | 全都有 | 全都有，节奏一致 |

两种模式共用同一套系统与平衡数值，只在「世界怎么建、玩家在不在场上、怪从哪来」上分支
（见 `src/data/modes.js`）。纯塔防不需要角色，是因为玩法重心在塔与科技上；
把角色删掉会让几十处读 `run.player` 的代码崩掉，所以实现上是让玩家**不存在于场上**：
位置锁在基地、标记为 dead 且不允许复活 —— 所有索敌本来就跳过 dead 的玩家。

### 材料稀有度

纯塔防没法出门采，但建塔、修墙、经营城镇都要纤维/木头/食物/水这些散装材料，
所以「地图材料」也进了怪物掉落表（见 `src/data/materials.js`）：

| 档位 | 材料 | 起始怪物等级 | 概率 |
|---|---|---|---|
| 常见 | 纤维 · 木质 · 食物 | 1 | 42% |
| 普通 | 冷凝水 · 甲壳 · 生物质 · 硫磺 | 1 | 26% |
| 少见 | 金属 · 晶体 · 零件 · 燃料 | 2 | 16% |
| 稀有 | 冷却剂 · 孢子 | 3 | 9% |
| 珍稀 | 研究资料 · 基因样本 | 4 | 5.5% |
| 极稀有 | 数据核心 · 吸引核心 | 5 | 3.5% |

精英 ×2.2、Boss ×4 的掉落权重；等级越高的怪掉得越多。
**低级怪碰不到高稀有档**，所以「晶体/数据核心」这类东西仍然要靠打硬仗换。

## 设置

主菜单和暂停菜单里都有【设置】。三项：

**按键绑定** —— 每个动作都能改，一个动作可以绑多个键（点 `+` 追加）。
点键位徽标上的 `×` 删掉某一个键；删到最后一个会自动回退默认键
（动作永远不会变成「不可触发」）。想占用别的动作唯一的键会被拒绝并提示，
避免把那个动作悄悄弄没。`Esc` 不能绑定（它是改键界面的取消键）。

键位存在 `localStorage`（键名 `frontier-settings-v1`），和存档分开 ——
换存档不该把键位也换掉。**改完立即生效**，不用重启。

**显示** —— 全屏 / 窗口化、窗口大小预设（自动 / 小 / 中 / 大 / 1280×720 / 1600×900 / 1920×1080）、
界面缩放（自动 85%~190%，也可手填 100%~175%）、帧率显示。

界面缩放的含义值得说清楚：**游戏画面本身不缩放**，窗口大就看到更多地图
（这是玩家想要的）；缩放的是 HUD、面板与字体。做法是在 `:root` 上设
`--ui-scale`，样式表里所有尺寸都写成 `calc(Npx * var(--ui-scale, 1))`
（由 `tools/scale-css.mjs` 自动改写，可重复运行）。

桌面版走 Electron 的窗口 IPC（`electron/main.cjs` 的 `window:*` 通道），
浏览器里全屏用 Fullscreen API，窗口大小多数浏览器不允许脚本改 —— 会给出提示。

**游戏性** —— 伤害飘字、屏幕震动、始终自动收集、掉落通知，以及模式切换。

**手柄和键鼠可以随时混用**：动一下鼠标就切回鼠标瞄准，碰一下摇杆就切回手柄。
用手柄逛面板时会显示一圈琥珀色焦点环，底部也会出现对应按键提示条
（提示条内容跟着上下文变：放置模式、站在载具旁、面板里显示的都不是同一套）；
受伤、爆炸、巢穴摧毁等事件会触发手柄震动。

接线位置：`src/core/gamepad.js`（输入映射 + 界面空间导航 + 震动）。
它把按键**注入成和键盘完全相同的动作名**，所以战斗/建造/面板代码一行都不用改。
提示条的文案在 `src/ui/gamepadHint.js` —— 加按键时两边要一起改，
`tools/gamepadMap.cjs` 会检查映射表，`tools/gamepad.cjs` 会检查提示条里
必须出现每一个键。

## 核心循环

```
               ┌──────────────────────────────────────────┐
               │  吸引装置（等级越高 → 拉到的巢穴越远越强）  │
               └───────────────┬──────────────────────────┘
                               │ 按牵引强度从范围内巢穴抽怪
                               ▼
   怪潮来袭 ──► 回基地防守（防御塔自动开火，可手动接管一座）
       │                       │
       │ 不回去                │ 击退
       ▼                       ▼
   基地掉耐久            结算金币 + 研究资料
   （被摧毁则人口全灭、    + 自动回收（需科技）
    装置停机、怪潮转为     + 升级 → 实验科技选择
    追杀你）                     │
                               ▼
                    升级吸引装置 / 清巢穴 / 出门探索
                               │
        清巢穴 = 永久降低压力，但永久少了刷怪收益 ← 核心取舍
                               │
                               ▼
                  清光所有巢穴 → 占领星球 → 继续经营 or 开拓下一颗
```

### 关键设计取舍

- **清巢穴 vs 不清**：不清 → 怪更多、金币经验更多、基地更危险；
  清了 → 压力永久下降、推进主线，但这条收益线永久变小。
- **吸引装置等级**：等级越高，牵引半径与强度越高。这是「主动调难度换收益」的旋钮。
- **回家的压力**：基地需要玩家**亲自**在范围内按 E 维修；被摧毁后要亲自重建。
  所以你不能无限期在外面刷。
- **基地被毁的连锁反应**：人口全灭 → 吸引装置停机 → 所有怪潮改为追杀你。
  此时再死一次 = 游戏结束。
- **塔防科技跨星重置**：新星球要重新申请空投授权，但角色等级、装备、
  实验科技、主科技树全部保留 —— 降低新星球前期的重复劳动。
- **降落点分三级**：地图上永远有且只有一个**一级（绿）**降落点，附近没有虫巢，
  是保底的新手起点，默认选中；二级（黄）/ 三级（红）危险度递增、贴着虫巢，
  但出门就是高价值资源。危险度按「附近虫巢威胁加权距离」算，排序后强制把
  最安全的一个降为一级 —— 保证再难的星球也有一个能活下来的落脚点。
- **Boss 住在巢穴里，不追人**。Boss 有一个「守门半径」（460px）：玩家不靠近，
  它就在巢穴旁踱步；玩家跑远了，它会脱战回巢，绝不一路上门。
  没有这条规则时，流场的共享目标会让它从地图另一头直接走到基地来 ——
  也就是「刚落地就有 Boss 追着你打」。普通巢穴守卫可以追出去 980px，超出就回巢。
- **开局不出精英怪**：前 150 秒、或者玩家没到 5 级之前，不刷精英
  （Boss 不算 —— 它老老实实待在巢里，玩家不惹就不会遇到）。
  精英是「三倍血的硬点」，开局只有一把初始武器时撞上纯属劝退。

## 地图尺寸与流场分辨率

世界边长 `WORLD_TILES = 304`（304×40 = 12160px），面积约为最初 176 格版本的 **3 倍**。
放大之后有两件事必须一起改，否则「地图变大」只会变成「多了很多空地」：

1. **按面积缩放内容密度**。`MAP_SCALE`（= 当前面积 / 原面积）乘在巢穴数量、
   遗迹/方尖碑/vault 数量上，保证单位面积的遭遇密度不变。
   判断标准：凡是「每个区域该有几个」的乘 `MAP_SCALE`，
   凡是「一个单位的感知范围」的（视野、leash、刷怪半径）都不乘。
2. **流场降采样**。流场是整图 Dijkstra，节点数随面积增长。304 格 + 逐格流场
   实测一次重算要 **20.7ms**，而它每 0.45 秒就要重算一次 —— 直接变成周期性卡顿。
   现在 `FLOW_CELL = 2`（一个流场格 = 2×2 地块），节点数降到 1/4，
   重算回到 **3.7ms**。方向场几乎没变，因为贴墙滑动本来由 `tryMove` 逐块判定，
   流场只负责给大方向。逻辑冒烟测试的模拟速度也从 1287 步/秒回到 **6500+ 步/秒**。

改这两个数字之前先跑 `node tools/mapbench.mjs` 和 `node tools/flowbench.mjs` 量一遍。

## 载具：为什么它被关在科技树后面

**开局只能步行。** 这不是限制，是节奏设计：

- 步行的活动半径就是基地周边那一圈资源，采完就该攒材料去申请载具
  （科技树 → 远征探索 → 「载具申请 · 拓荒运输车」，180 金 / 70 金属 / 12 零件）；
- 载具到手之后，更远、更值钱、也更危险的资源点才真正进入你的活动半径。

载具的速度被刻意压到 **240**（步行的 1.4 倍，原来是 1.7 倍）。
太快会让地图在体感上变小 —— 想去哪儿都是一脚油门，跑图这件事本身就没有分量了，
「攒材料申请载具」也就失去了意义。现在你仍然要算油量和回程。

**载具的科技线比防御塔短得多**，这是故意的：它是一条工具线，不是第二条战斗线。

| 层 | 节点 | 作用 |
|---|---|---|
| 1 | 载具申请 | 解锁载具本身 |
| 2 | 引擎 / 破障撞角 | 速度 +18% / 撞击 +14 |
| 3 | 炮塔挂架 / 旋切电锯 | 2 个炮塔挂架（上限就是 2）/ 撞击 +30 且附带流血 |
| 4 | 装甲与武器 | 耐久 +80%，被别住时间 -40% |
| 5 | 悬浮底盘 | 无视地形减速，速度再 +30% |

**精英怪会别住载具。** 车在野外原本太安全：有速度、有油、有装甲，一路碾过去就行。
现在精英怪（和 Boss）撞上来不是被撞飞，而是把车**别停** 1.1~1.6 秒，
期间油门无效、车体还会掉血。于是「野外遇到精英」重新变成一个要下车解决的麻烦：
下车打（暴露在野外），或者倒车绕开（浪费油和时间）。装甲科技能缩短被别住的时间。

## 装备与品质

五档品质，颜色即稀有度：

| 色 | 内部 id | 词缀条数 | 从哪来 |
|---|---|---|---|
| 白 | `common` | 0 | 随处可见、城镇初级工坊 |
| 绿 | `uncommon` | 1 | 普通掉落、标准工坊 |
| 黄 | `rare` | 2 | 精英怪主力产出、精密工坊 |
| 紫 | `epic` | 3 | 精英 / Boss / 废弃基地、**高级军械库（城镇上限）** |
| 红 | `relic` | 4 | **只能靠打**：Boss 10% / 废弃基地 5% / 虫巢深处残骸 5% |

**红色装备必带一条专属特殊效果**（`RED_EFFECTS`，见 `data/weapons.js`），
而且这些效果是「改变玩法」而不是「再加一点数值」——
否则红装只是数字更大的紫装，玩家不会为它兴奋。
例如血偿（伤害吸血）、相位残影（闪避冷却 -40% 且留下伤害残影）、
移动堡垒（静止 2 秒获得护盾）、虫群威压（附近每只敌人 +4% 伤害）。

### 掉落规则

| 来源 | 规则 |
|---|---|
| 精英怪 | **15%** 掉一件「紫色及以下」，品质随怪潮波次上升（`eliteRarityBonus`） |
| Boss | 必掉 3~5 件紫及以下，另有 **10%** 出一件红色 |
| 废弃基地 | **35%** 开出一件紫及以下，另有 **5%** 开出一件红色（独立判定） |
| 虫巢深处残骸 | **5%** 开出红色 + 一批稀有材料 |
| 普通怪 | 1.2%（受幸运影响） |

### 护甲与城镇制造

角色**开局自带一件白色简易护甲**——「装备护甲」这条线从第一分钟就成立。
护甲线共 7 件（`fieldJacket` → `aegisShell`），靠掉落或制造获得。

制造在城镇的【军械工坊】里（需要先造这座建筑，定居点等级解锁）：

- 能造什么品质由**人口等级**决定：前哨站白色 → 定居点绿色 → 殖民镇黄色 → 拓荒城市紫色；
- **红色永远造不出来**——保证最强的那一档只能靠冒险；
- 同一件东西可以选品质制造，品质越高越贵，黄/紫还要吃晶体与零件。

## 虫巢副本

巢穴分 **10 级**（`_nestTierFor`，离地图中心越远越高）。
站在巢口按 **F** 进入副本，布局是「鱼骨刺」：

```
入口 ══╤══════╤══════╤══════╤══► 💀 Boss 房
       │      │      │      │
     侧室   侧室   侧室   侧室
```

- **主通道**保证「永远知道往哪走」，不会在迷宫里转圈；
- **侧室**是可选收益：被拖进来的旗舰残骸（`wreckCache`），
  5% 开红色装备 + 一堆稀有材料。要不要拐进去是个取舍；
- **最深处是 Boss 房**，进去之前你有一整条通道的时间后悔；
- 巢穴等级决定侧室数量、通道长度、残骸数量与 Boss 强度（10 级 Boss 血量约 1 级的 3.5 倍）；
- **巢穴被毁后不可再进入**。通关副本 = 巢穴被端掉，永久不再产怪。

实现上世界是**就地改造**的：`world/dungeon.js` 把地块数组整片填成巢壁再挖出通道，
洞外全实心 —— 所以碰撞、寻路、渲染、存档全都复用现成代码。
副本是**另一个 RunState**（`run.dungeonRun` / `run.overworldRun` 互相引用），
外层世界原封不动地留着；出口时把经验、金币、材料搬回去。
在入口按 F 随时撤退（战果保留）。

### 副本地图（M）

在副本里按 `M` 打开的是**虫巢地图**而不是行星地图
（`src/ui/panelDungeonMap.js`）—— 行星地图那里只会显示一堆几乎全黑的地块，
什么也读不出来。

虫巢地图画的是一张**示意图**：主通道一条横线，侧室挂在上下两侧（上下交替），
最右端是巢核。它解决的问题是「玩家在通道里跑，不知道自己走到哪一段、
还有几个侧室没搜」：

- **入口**与**巢核**始终标出 —— 你需要知道回程点和目标在哪；
- **旗舰残骸**用菱形标出，走近之前是亮色（暗示「这里有东西」）；
- **探索迷雾**：走过的通道段、进过的侧室才点亮，没进过的侧室显示 `?`；
- 底部有一条**进度条**，直观表示「离巢核还有多远」。

迷雾不做持久化：退出副本再进来就是一次新的探索（巢穴是活的），
也省掉一份要序列化的状态。

## 设置与操作说明

主菜单与暂停菜单里都是同一个入口（**设置与操作说明**），四个页签：

- **按键绑定** —— 26 个动作全部可改；一个动作能绑多个键；点键位徽标上的 `×` 删单个键；
  删到最后一个自动回退默认键（动作永远不会变得不可触发）；想占用别的动作唯一的键会被拒绝。
- **操作说明** —— 键盘表**从设置实时读**，改完键立刻一致；另有手柄表、两种模式、
  核心循环、失败条件。这一页原来是一个独立按钮，那份按键表是手写的，
  和「按键绑定」页各写一份、改一处另一处不会变 —— 所以并了进来。
- **显示** —— 全屏 / 窗口化、窗口大小预设、界面缩放、帧率显示。
- **游戏性** —— 伤害飘字、屏幕震动、始终自动收集、掉落通知、模式切换。

`Esc` 关面板的行为有条特殊规则：设置面板开着时按 `Esc` **只关设置、保持暂停**
（不能顺手把游戏也取消了，否则玩家会以为「一关设置就自动继续了」）；
其他面板开着时按 `Esc` 打开暂停菜单；都没有时才是「暂停 / 继续」切换。

## 素材：现在是「可选层」，可以一块一块地接

项目至今**零外部素材**（全程序化图形），但素材层已经搭好了，
接素材是纯增量的 —— 往 `assets/` 里丢文件 + 改 `assets/manifest.json`，
不需要动游戏逻辑，也不会因为漏了某个文件就崩：

```
assets/manifest.json    逻辑名 -> 文件路径
assets/tiles/           terrain.<地块ID>      例 "terrain.2": "tiles/grass.png"
assets/props/           prop.<可采集物type>
assets/enemies/         enemy.<怪物type>
assets/towers/          tower.<塔id>
assets/ui/              ui.*（HUD 与面板，DOM 侧用 CSS）
assets/fx/              fx.*（爆炸 / 枪口火焰）
```

`src/core/assets.js` 的 `AssetManager` 会读 manifest 并预加载；
**任何一个文件缺失或加载失败，那一个对象就静默回退到程序化绘制**，
其余继续用贴图。所以可以今天只换草地、明天换一只怪，随时保持可玩。

已经接上贴图钩子的地方：地形（`renderChunk`）、可采集物（`drawPropShape`）、
怪物（`drawEnemyBody`）。加新钩子就是三行：`this.assets?.img('前缀.' + id)`，
有就画、没有就走原来的分支。

素材候选清单与**逐条验证过的直链**见：
- `assets/ASSETS.md` —— 完整调研（128 个链接，含体积/内容核对、目录规范、ID 约定）
- `assets/ASSETS-VERIFIED.md` —— **要下载的那几个包的复验记录 + 可直接粘贴的下载命令**

> 复验是「状态码 **和** 字节数都与记录一致」才算通过 —— 只回 200 但体积变了，
> 说明对方换了文件，需要重新核对内容。

## Steam 上架适配

代码侧已经接好，**剩下的是 Steamworks 后台的账号操作** ——
完整清单见 [`steam/STEAM-CHECKLIST.md`](steam/STEAM-CHECKLIST.md)。

| 已做的 | 位置 |
|---|---|
| Steam 桥，**没有 Steam 时全部静默降级** | `electron/steam.cjs` |
| 12 个成就的触发点集中在一处 | `src/main.js` 「Steam 成就」一节 |
| 渲染侧客户端（浏览器里也能安全调用） | `src/core/steamClient.js` |
| IPC 白名单 `status/unlock/setStat/store/list` | `electron/preload.cjs` |
| Steam 覆盖层（Shift+Tab） | `electron/main.cjs` |
| `electron-builder` 打包配置（`asarUnpack` 处理原生模块） | `package.json` → `build` |
| 构建脚本模板 | `steam/app_build.vdf.example`、`steam/depot_build.vdf.example` |

**为什么 Steam 走 IPC 而不是按官方文档在主进程直连**：`steamworks.js` 的 README
要求在渲染进程里开 `contextIsolation: false, nodeIntegration: true`，
那等于把整个 Node 环境交给页面脚本。这里把 Steam 放在主进程、只暴露一层很窄的 IPC，
和现有的存档桥是同一套做法。

一键打包与截图：

```bash
npm run dist:dir    # 产出 dist/win-unpacked（electron-builder）
npm run shots       # 关键界面截图 -> tools/shots/（人工看视觉）
```

> 打包前记得把 Steamworks 的 `steam_api64.dll` 放进 `dist/win-unpacked/`，
> 并确认里面**没有** `steam_appid.txt`（那是开发调试文件，不能进正式包）。

## 建造模式是「时停」的

按 `B` 的完整流程：

1. `B` → **暂停游戏** + 打开建造面板
2. 点一张塔卡 → 进入放置模式，**仍然暂停**（怪不动、塔不打）
3. 左键落点 → 建成，**留在放置模式**，可以连着放好几座
4. `B` / `Esc` / 右键 → 结束建造，回到面板（仍然暂停）
5. 关掉面板 → 恢复游戏

以前不是这样：面板卡片里写的是 `modals.close(); startPlacement(...)`，
而 `modals.close()` 会触发面板的 `onClose → game.paused = false`。
结果「放置模式」其实是在**跑着的游戏里**放置 —— 怪在动、塔在打，
而且那时候左键既落点又开火：**按 B 想建东西，角色却对着地面开枪**。
现在 `startPlacement()` 自己负责暂停，不再依赖调用方的顺序。

### 暂停时键盘输入不能失效

`postUpdate`（处理面板开关、暂停键、放置落点）原本挂在 `Game.update()` 里，
而 `update()` 只在「playing 且未暂停」时跑。于是**一旦暂停，所有键盘输入全失效**：

- `Esc` 关不掉暂停菜单（只能拿鼠标点「继续游戏」）
- 建造模式本身就是暂停的，所以按 `B` 退不出来 —— 人卡在放置模式里
- 玩家报的「不能退出游戏」和「建筑模式退不出」都是这一条

现在暂停/菜单状态下改由 `beforeFrame` 调用 `postUpdate`，每帧仍然只处理一次。

## Boss 只在虫巢里面

地表的巢穴**不刷 Boss**。以前每个巢穴会在玩家靠近 900 像素时孵出一只
「巢穴吞噬者 / 虚空女妖」，于是走到巢穴边上就能看到 Boss 蹲在外面 ——
但 Boss 按设定是**副本最深处的守关怪**：它需要副本房那样的场地，
也需要「深入 → 打 Boss → 通关」的节奏。摆在野地里只是凭空多了一只血厚攻高的怪。

现在地表巢穴只有普通守卫（`spawnNearNest`），Boss 只由 `spawnDungeonBoss()`
生成 —— 也就是玩家真的走进副本、走到最深处的房间里时。

## 采集

- 采集产出**一点一点跳**：每 0.6 秒结算一小块，并从材料**上方**飘出 `+N`，
  而不是在右下角显示一个百分比。采集过程本身就有反馈。
- 采掘镐科技（`t_mine1..4`）每次产出 **+1**：+2 / +3 / +4 / +5。
  它**只提升效率**，不改变能采到什么。
- **植物会再生长**（纤维灌木 95 秒、孢子树 150 秒…），**矿物不会**
  （铁矿脉、晶簇、残骸堆的 `respawn` 是 0，采完永久消失）。
  HUD 的采集提示会直接标出「可再生 / 不可再生」。

## 自由降落点

开局不再是从 4 个固定点里挑一个：**在地图上任意点一下**就能把核心舱降在那里。
落点必须是一块放得下核心舱的平地（`world.evaluateLandingSite()`）——
水域、岩壁、世界边界、压在虫巢上都会被拒绝，并给出具体原因。
原来的 4 个点保留为「系统推荐」（1 号必定是最安全的那块），点一下就能选。

界面上实时显示：坐标 / 生物群系 / 危险度（安全·警戒·危险）/ 1000 内虫巢数 /
资源丰度 / 地形危险 / 开阔度。

## 核心舱的吸引阵列（原「吸引装置」）

吸引装置不再是野外一台独立设备，而是**核心舱自带的一套阵列**：

- **被打爆 = 不再吸引**。核心舱被摧毁 → 阵列停机 → 虫群失去牵引，
  进入**追杀模式**，直接朝你扑过来（`director.startHunt('base')`）。
- **没了吸引物质也一样**。吸引物质（能量）耗尽 → 停机 → 同样进入追杀
  （`startHunt('fuel')`）。充能后只解除「缺能」这一种追杀，
  基地被打爆的那种要等你把核心舱重建起来。
- **消耗速度减半**：`BEACON.fuelPerSec 0.32 → 0.16`，`fuelPerWave 12 → 6`。
- UI 上「吸引装置」页签已经并进【基地与核心舱】那一页。

### 基地重建（按 E）

玩家报的「按 E 重建没反应」其实有**两**层原因，都修了：

**一、存档里漏了字段（真凶）**。`serializeBases()` 没存 `r`（交互半径），
`beacon.serialize()` 没存 `x/y`。读档之后 `base.r` 是 `undefined`，
而判定写的是 `dist < b.r + 40` —— `undefined + 40 = NaN`，任何比较都是 false，
于是**读档后按 E 永远没反应**（读档正是玩家的日常玩法）。
顺手也修了吸引阵列坐标丢失导致的「整波怪只剩一个巢贡献」。
现在存档往返会被断言盯住（`smoke.mjs`「读档后核心舱交互半径还在」等 4 条）。

**二、手感问题**：

| 原因 | 现在 |
|---|---|
| 要按住整整 45 秒 | `BASE.rebuildTime = 12` |
| 「点一下」完全不算数 | 每点一下推进 `rebuildPerTap = 0.55` 秒 |
| 没有任何进度反馈 | 废墟上画进度环 + 百分比，HUD 提示也带百分比 |
| 站在废墟旁却去采旁边的灌木 | 废墟范围内 E 一律是重建（`updateHarvest` 最前面判定） |

这条教训值得单独记一笔：**「NaN 比较永远为 false」是最难查的一类静默失败** ——
没有报错、没有日志，功能就是「不响应」。凡是 `a < b + c` 这种判定，
两边的字段都必须进存档、并且默认值要兜住。

## 刷怪位置：从虫巢，或从屏幕外沿

`director.spawnPoint(prefer)` 一条规则管住所有刷怪（怪潮、巢穴守卫、野外怪、追杀潮）：

| 情况 | 行为 |
|---|---|
| 巢**在屏幕里** | 从巢口刷 —— 玩家看得见虫子从洞里爬出来，这是想要的效果 |
| 巢在屏幕外，且离玩家**足够远**（> 视野半径 + 缓冲） | 也从巢里刷，它们自己走过来 |
| 巢在屏幕外，但**离玩家太近**（就在屏幕边上） | 沿「玩家 → 巢」方向推到屏幕外 + 缓冲处 |
| **没有巢**（追杀潮 / 野外游荡怪） | 屏幕外沿随机方向 |

> 这条规则改过三版，值得记下来：
> 1. 一开始「巢在屏幕外也从屏幕外沿刷」—— 整波怪直接贴到基地门口，第一波推平 6 座塔；
> 2. 改成「有巢一律从巢里刷」—— 玩家反馈「虫子还是刷在基地周围，像凭空冒出来」，
>    因为吸引范围（900px）内的巢本来就围着基地；
> 3. 现在这版：**看巢在不在屏幕上、够不够远**，两头都占住。
>
> 另外「玩家在吸引阵列范围内时优先打基地」的判定，量的必须是
> **玩家 ↔ 阵列**的距离，不是玩家 ↔ 怪 —— 后者会把「怪离玩家很近」也误判成
> 「玩家在范围内」（这条被 `smoke.mjs` 的索敌断言抓过一次）。

## 防御塔基座：它才是「取消间隔」的那个东西

规则（玩家澄清过：**不是「相连加成」**）：

- 塔放在**空地**上时，彼此必须保持间隔（`TOWER_GAP = 44px`，比一格略大）；
- 塔放在**【防御塔基座】**（`turretSlot`）上时**不需要间隔**，可以一座挨一座摆成火力阵列。

这条也是**基座存在的意义**。之前它之所以鸡肋，是因为一个死结：
`findPlacement` 的「建筑冲突」检查把基座自己也算了进去，
于是**塔永远放不到基座上** —— 基座只是一块更贵的空地。

实现要点：

| 位置 | 代码 |
|---|---|
| 判据「站在基座上」 | `TowerSystem.platformAt(x, y)`（`PLATFORM_R = 26`） |
| 间隔只在空地上生效 | `findPlacement(..., { forTower: true })` |
| 铺基座不被旁边的塔挡住 | `findPlacement(..., { forTower: false })` |
| 基座自己不算建筑冲突 | 跳过 `s.type === STRUCTURE.TURRET_SLOT` |
| 可视反馈 | 坐在基座上的塔画一圈绿底座 + 基座指示灯（`drawTowerPlatforms`） |

> 顺带修了一个真 bug：`fire()` 里算了 `rateMult = 1 + vengeanceRate`
> 却从来没使用 —— 「复仇协议」的**攻速加成一直完全无效**。
> 现在它作用在 `t.cd = t.attackCd / (1 + vengeanceRate)` 上。

## 虫巢副本的内容：残骸 / 守军 / Boss 技能组

### 残骸太多 → 金属堆

有个隐蔽的 bug 让地表「到处都是旗舰残骸」：`wreckCache`（旗舰残骸，5% 出红装）
的 `biome` 是 `undefined`，而 `_pickPropType` 的过滤条件是
「有 biome 且不含当前群系才跳过」——于是它被当成**常规物**撒满了地表。
实测一小片区域就有 **24 台**，等于在地表刷红装。

| 改动 | 说明 |
|---|---|
| `wreckCache` 移出常规池 | 它是副本专属（`_setupDungeon` 手动摆） |
| 新增 `metalHeap`（金属堆） | 纯材料（金属 6~12 / 零件 2~5 / 偶尔晶体），**不掉装备** |
| 地表 `wreck` 有 50% 变成金属堆 | 残骸本身重新变得值得留意 |
| 副本旗舰残骸上限 3 台（+ Boss 房门口 1 台） | 以前是 `1 + 层数/3` 台并挤在一条线上 |
| 副本金属堆 `3 + 层数×0.6` 堆 | 铺在其余侧室，材料产出不断 |

### 副本不只有 Boss：固定数量的守军

`spawnDungeonGarrison(tier)`（第一次 `update` 时铺开，因为构造 RunState 时战斗系统还没装配）：

- 每间侧室 **1 只**（7 层以上 2 只）守着宝物；
- 主通道 `2 + 层数/3` 只巡逻；
- 全部用 guard 逻辑（离原位 980px 内追击、超出回位），不会一路追到入口大厅。

10 级巢穴实测 **17 只**，怪种从甲盾虫到潜猎者都有。

### 巢穴主的三件套

副本 Boss 不再只有一个技能，而是带一组、各自独立冷却（`e.abilities`）：

| 技能 | 表现 | 参数 |
|---|---|---|
| **冲撞** | **红色感叹号 + 红色冲撞走廊**预警 1.1 秒，然后沿锁定方向高速撞过去 | 520px / 980px·s⁻¹ / 2.2× 伤害，撞墙会自己停下并被震住 |
| **弹幕** | 朝玩家方向扇形撒 7~12 发弹丸，分 2 波 | 0.45× 伤害，弹速 330 |
| **召唤** | 钻出 2~6 只小怪（场上最多 8 只） | 冷却 16s |

预警期间 Boss **不走位也不出手**，角度在起手瞬间锁死 —— 玩家有 1.1 秒侧移躲开，
这才是「预警」的意义。视觉上除了头顶的红色「!」，还会画出冲撞走廊，
明确告诉你**往哪边躲**。

> 写这段时自己踩了一个坑：`if (e.dash)` 的结算最初放在「没有目标」判断**后面**，
> 于是玩家一跑远、Boss 一丢目标，`e.dash` 就永远挂在身上 ——
> 它会拖着红色尾迹慢慢晃，而冲撞距离再也不推进。
> 单次冲撞从 32 帧变成 **288 帧**，是靠逐帧计数才抓出来的（`smoke.mjs`
> 现在有一条「冲撞会正常结束（不会挂在身上）」盯着它）。

## 虫巢副本：整张图都是巢穴风格

进副本时世界会被就地改造（`world/dungeon.js`）。以前只把世界中间一小块填成巢壁、
区域外留成**虚空**，两个后果玩家都报过：

- 虚空和巢壁都是接近黑的颜色 → 分不清「这是墙」还是「能走」；
- **地表世界的障碍物没被清掉**（实测副本里还剩 72 个灌木/岩石 props），
  照旧画在虚空上 → 「虫巢里的地形怎么和外面一个风格」。

现在：`world.tiles.fill(T.NEST_WALL)` + `props.clear()` + 巢穴/遗迹清空，
整张图只有巢壁与巢道两种材质。小地图只画 `dungeon.region`，
渲染只画视野内的区块，所以「填满全图」既不掉帧也没有风格割裂。

### 为什么「地形数据对了，画面还是地表」——渲染层的区块缓存

改完地形之后玩家依然报「虫巢里还是地面风格」。原因是**渲染层的区块缓存键**：

```js
// 之前：只按区块坐标缓存，用 tileRevision 判失效
const key = cx + ',' + cy;
if (cached.rev === (world.tileRevision || 0)) return cached.canvas;
```

副本是**另一个 `World` 对象**，但坐标完全一样，而两个世界的 `tileRevision`
都是 0（`carveDungeon` 直接改数组、没走 `setTile`，所以版本号根本没动）——
于是渲染层判定「没变」，把**地表的区块图**直接贴进了巢道里。
陆测出来的数据全是对的（`tiles` 全是 16/17/18），画面却是地表。

修法：

| 改动 | 位置 |
|---|---|
| 每个 `World` 一个自增 `uid` | `world.js` |
| 区块缓存键 = `uid:cx,cy`，并且额外比一次 `world` 引用 | `renderer.getChunk()` |
| 小地图底图同样记住 `world.uid` | `hud.buildMinimapBase()` |
| `carveDungeon` 结尾显式 `tileRevision++` | `world/dungeon.js` |

好处还有一个：两个世界的区块缓存**共存**，进出副本都不用重建，回地面是瞬间的。

### 核心舱不跟着你下副本

玩家的原话是「不用把基地也跟我一起下来吧」—— 确实很怪。现在进副本时：

- 核心舱被挪到世界之外（`b.x = -9999` + `b.parked = true`），副本里**没有基地**；
- 所以巢里不能建塔、不能修基地（建造范围不在场）；
- 指南针改成指 **入口（F 撤退）** 与 **巢穴主**，不再指一个不存在的基地；
- 死了会在**入口大厅**醒来（以前会按 `base.x + 70` 复活 → 直接掉到地图外）；
- 流场目标在副本里改成**玩家**（核心舱在世界外，照着它算会让整条巢道的怪走向地图角落）；
- 撤退仍然是「走回入口按 F」（`updateDungeonExit`）。

## 输入手感：为什么按键不会「按了没反应」

所有操作都走同一套「动作名」通道（键盘 / 鼠标 / 手柄注入的是同一个名字），
并且按下的边沿事件不会被直接丢掉，而是进一个 **160 ms 的输入缓冲**
（`src/core/input.js` 的 `pressedBuffered` / `consumeBuffered`）。

原因是很多动作有前置条件：体力不够不能闪避、附近没车不能上车、没目标不能采集。
条件不满足时那次按下以前就白费了，玩家必须「再按两三遍」——这就是原来手感发粘的根因。
现在按下的意图会留在缓冲里，条件一满足立刻生效，且**只生效一次**（不会因为
缓冲窗口连着触发两下）。

手柄按键更特殊：手柄没有「按下 / 抬起」事件，只有每帧的状态快照，
所以实现成**每帧重新注入**——上一帧注入过、这一帧没有再注入的动作，
会在 `endFrame()` 里被判定为「已松开」并从 `down` 里删除
（见 `_padPrev` / `_padHeld`）。少了这一步，按一次的键会永远卡在按住状态。

回归测试：`tools/inputBuffer.mjs`（18 项）、`tools/gamepadMap.cjs`（19 项，含「A 松开后必须解除」）。

| `ECON` | 初始资源、金币系数、升级曲线 |

| `MAP_SCALE` / `FLOW_CELL` | 内容密度缩放 / 流场降采样倍数（见上文「地图尺寸与流场分辨率」） |
| `ECON.xpScale` | 经验需求倍率（1.5 = 实验科技慢 1.5 倍，见下） |
| `VEHICLE` | 载具速度 / 油耗 / 炮塔上限 / 近战模块位（见「载具」一节） |
| `RENDER.maxDPR` | 高分屏最大像素比（性能与清晰度的取舍） |

内容数值在 `src/data/` 下各自的表里（怪物 HP/伤害、塔的 DPS、科技费用、实验卡效果、
材料稀有度 `materials.js`、制造费用 `crafting.js`、副本规模 `world/dungeon.js`）。

### 经验曲线与「一波一次实验科技」

升级 = 属性与生命成长，**不再**直接送实验科技四选一。
`ECON.xpScale = 2.8`（原来是 1.5）把每一级的需求整体抬高，
而实验科技的主要来源改成了**打退一波怪潮 +1 次**（`director.endWave`）。

为什么这么改：升级送选择次数的版本里，一场下来能攒出二十多次四选一
（截图里那句「获得 25 次实验科技选择」就是这个），实验科技从「成长事件」
变成了弹窗疲劳。现在是「守住一波 ≈ 抽一次」，节奏和玩家实际经历的事情对齐。
`smoke.mjs` 会断言「升级本身不送实验科技」「打退一波给 1 次」「超时不给」。

等级变了之后，塔防模式的前期压力也会跟着变 —— 所以纯塔防开局多给了一批启动资源
（见 `data/modes.js` 的 `startResources`），否则第一波会因为「塔不够、科技也没起来」而必崩。

### 弹药与武器成长

- **弹药永远是整数**。等离子/喷火这类武器的 `ammoPerShot` 是 0.15，
  直接相减会让界面显示 `159.85`。现在不足 1 发的零头记在 `player._ammoFrac`，
  攒够 1 才真的扣 1 发（`player.spendAmmo`），消耗速度不变、显示永远干净。
- **弹仓只有一个数**：`PLAYER.ammoStart = 160 / ammoMax = 200`。
- **打空自动换弹**：没子弹了立刻自动开始换弹（`run.beginReload(true)`），不用记 R 键；
  R 仍然可以提前手动换。**换弹时间按武器与品质给**：
  `RELOAD_BY_WEAPON`（手枪 1.2s、磁轨 2.6s…）× `RARITY_RELOAD`（白 1.0 → 红 0.78）。
  空仓干等不再白送子弹（`reloadPending` 区分「花钱换弹」与「干等」）。
- **怪会掉子弹**：普通怪 55% 掉 5~10 发，精英必掉 8~15 发，Boss 12~15 发
  （`loot.rollAmmoDrop`）。子弹拾取直接进弹仓，不占仓库。
- **武器四条线在科技树的【武器火力】分支**：射程 / 伤害 / 射速 / 弹道，
  上限分别是 300% / 300% / 200% / 3 条，加满正好封顶。
  上限由 `WEAPON_CAPS` 在 `player.weaponStat()` 里强制执行 —— 装备词缀、
  实验科技、红装特效都能往上叠，但总和不会超过这个数。
- **捡到武器**：快捷栏（4 格）有空位就放进去，满了才进背包。
  数字键 1–8 对应快捷栏 1–8（5 = 装填，6/7/8 = 医疗包 / 兴奋剂 / 维修套件）。
- **修塔**：走到受损的防御塔 / 工事 / 城镇建筑旁按住 **E**，
  按金属消耗逐点回耐久，速度吃维修类科技；HUD 会直接写出
  「按住 E 维修 哨戒炮台（耐久 52% · 消耗金属）」。

### 护甲：头盔 / 胸甲 / 护腿

护甲拆成三个部位，各自一条装备线（`EQUIP_DEF` 里的 `helmet` / `chest` / `legs`）：

| 部位 | 特点 | 装备栏下标 |
|---|---|---|
| 头盔 | 护甲 + 少量生命（高级的带视野） | 0 |
| 胸甲 | 护甲最高、生命最多（重甲有移速惩罚） | 1 |
| 护腿 | 护甲 + 移速 / 闪避 | 2 |
| 饰品 | 两个槽 | 3 / 4 |

开局自带的是胸甲【简易护甲】。旧存档里那件单件「护甲」在读取时会自动迁移到胸甲槽
（`restorePlayer` 按数组长度识别旧布局）。**背包有排序键**：品质 / 部位 / 评分 /
负重 / 名称。城镇工坊里三条件都能造。

### 怪物卡地形

流场是 2 格降采样的，而实际移动用逐格的 `circleBlocked` —— 两者在墙角与窄缝处
会不一致，表现是「一只怪贴着石壁原地抖」。`enemies.unstick()` 兜底：
连续 1.2 秒几乎没位移、又不在攻击距离内，就把它挪到最近的可通行点。

### 看得见的崖边（空气墙问题）

玩家反馈「同样的材质看着能走，撞上去是空气墙」：火山灰（`#4a4340`，可走）和高山
（`#3c4048`，实心）在实机里几乎分不出来。现在只要实心地块挨着可通行地块，
`renderer.drawSolidEdge()` 就在交界处画一条亮边 —— 「这里是墙」不用再靠撞出来。

### 巢穴与 Boss 房

- 巢穴画成**虫子钻出来的洞**：外翻的土堆 → 向内塌陷的坡度 → 洞底的黑 →
  洞口抓痕 + 呼吸的红光。形状用巢穴 id 做种子，每个巢都不一样，
  但每次进游戏长得一样（用 `Math.random` 会让洞口每帧都在变形）。
- **Boss 房按巢穴等级放大**：T1–3 是 15×15 格，T4–7 是 19×19，T8–10 是 23×23，
  四角还有支撑柱（原来固定 11×11，大体型 Boss 加小怪就把房间塞满了）。

清巢穴 → 占领星球 → 开拓下一颗）。跑 `node tools/verify.mjs --all` 看当前断言总数

1. **虫巢副本的渲染**：地形（巢壁 / 巢道）已经能画出来，但侧室与 Boss 房还没有
   独立的装饰（巢核、卵堆、生物光）。现在只能靠地形颜色与 HUD 提示分辨自己在哪。

4. **生物学家深度**：基因缝合与驯化的数据结构与 UI 已通，驯化单位的独立 AI 还比较基础。
5. **第二基地**：可以建立并共享人口/科技，但两线同时防守的调度还很粗。

5. **打包分发**：`npm start` 可直接运行；要出安装包需再引入 `electron-builder`

6. **性能余量**：单帧实测在 60 帧稳定、堆内存约 7–13 MB；敌人硬上限 260，
   上百单位同屏时流场与分离开销会上升，届时应考虑把分离改为网格分桶。

## 开发笔记：踩过的坑

留几个对后续维护有用的教训：

- **流场必须量化成整数代价**。斜向代价含 √2，浮点累加会产生 1e-13 级别的
  「更优路径」，节点被反复重新松弛、堆无限膨胀、永不终止 —— 表现为游戏卡死 + 内存爆掉。
  现在 `FlowField.NEIGHBOR_COST` 用 1/256 像素为单位取整。
- **高速弹丸要扫掠碰撞**。900 px/s 的子弹一帧走 15 px，只在终点判定会穿过敌人。
- **`render` 里的异常会静默吃掉整个游戏循环**。一个 `TILE is not defined` 就能让
  世界不再生成、又没有明显报错。现在 `main.js` 里有全局 error/rejection 兜底，
  会把错误弹到通知栏。
- **不要整个区块地「屏蔽」障碍物生成**。基地预备阶段曾经把所在的 16×16 区块
  整块标记为不长东西，结果那张图几乎全是空的。现在按「投放点」级别屏蔽。
- **模态框的 z-index 必须高于主菜单**。`#modal-root` 原来是 40，`.menu-screen` 是 60 ——
  从主菜单点「设置」时面板**其实打开了**，只是被主菜单整个盖住：看不见，
  而且面板中心的点击命中的是主菜单的按钮（`elementFromPoint` 返回 `#mainmenu`）。
  玩家报的是「设置打不开」，所有断言却全绿，因为断言只验了「面板被创建」。
  **教训**：UI 层级这类问题断言很难覆盖，得有截图工具（`tools/screenshot.cjs`）。
- **暂停时键盘输入会整体失效**。`postUpdate` 挂在 `Game.update()` 里，而 `update()`
  只在未暂停时跑 —— 所以暂停菜单的 `Esc`、建造模式的 `B` 全都没反应。
  这类 bug 很隐蔽：逻辑本身没错，错的是「它在什么条件下才被调用」。
  现在暂停/菜单状态下由 `beforeFrame` 兜住。
- **「关面板」和「暂停状态」必须只有一个负责人**。面板卡片里写
  `modals.close(); startPlacement(...)` 看着没问题，但 `close()` 会触发
  `onClose → game.paused = false` —— 于是放置模式其实在跑着的游戏里进行，
  左键既落点又开火。修法是让 `startPlacement()` 自己负责暂停，
  不依赖调用方的顺序。
- **出生点不能落在「被占用的格子」上**。副本里基地和玩家都放在入口，
  而基地会把它所在的那一格标记为占用（`_syncBlockedTiles`）——
  玩家出生在基地那一格上 = 出生在墙里，**一步也动不了**。
  现在入口是一间大厅：基地靠左、玩家靠右。另外 `_moveWithCollision` 加了
  「卡墙自救」：如果当前所在点已经是 blocked，先朝最近的空地推出去，
  绝不允许玩家被永久钉住。
- **`StatSet` 的构造参数以前只进 `this.base`，不进 `this.flat`** ——
  而 `get()` 读的是 `flat`。于是 `new StatSet(角色基础属性)` 出来的属性表里，
  角色的护甲、暴击、生命回复**全是 0**，而且完全静默（不报错，只是数字不对）。
  一个「护甲 3」的角色挨打时按护甲 0 算，谁也看不出来。
  现在构造参数直接就是初始 `flat`。
- **解锁必须累加，不能只看「当前这一档」**。城镇建筑的解锁原本只查当前人口等级的
  `unlock` 列表，于是「定居点解锁工坊」这条规则在城镇升到拓荒城市之后就**失效**了 ——
  工坊突然变成造不了。现在遍历所有「已经达到过」的等级，达到了就不会再失去。
- **新加的地块类型要同时补 `TILE_DEF`**。副本用的巢壁/巢道一开始只加了常量，
  忘了加定义表，`isSolidTile` 直接返回 false —— 整面墙变成可以走过去的。
  好在这类问题会被「副本大部分是巢壁」这种断言抓住。
- **测试里的 `import()` 可能拿到另一个模块实例**。`const { settings } = await import(...)`
  在测试里会重新求值一次模块，改的是另一份单例；测试与游戏都从
  `window.__frontier` 取真实实例才对得上（详见「踩过的坑」上面那条）。
- **别在测试里依赖随机地图**。`deep.cjs` 的「采集 / 怪潮 / 载具」三条用例曾经
  因为「最近的资源点恰好是不能采的虫卵囊」「载具恰好停在山壁前」而随机失败。
  现在要么在开测前把地形整平、挑合法的目标，要么用固定种子重开一局。
- **`process.env` 在浏览器里不存在**。往 `src/` 里塞调试输出时用
  `process.env?.X` 或干脆别写 —— `process` 未定义会直接把那个函数打断。
- **`tools/checkimports.mjs` 是性价比最高的检查**：导入的名字必须在目标文件里
  真的被导出，几秒钟就能跑完，能挡住一整类只在深层代码路径才暴露的崩溃。
- **手柄按键要「每帧重新注入」，判断松开必须用上一帧的集合**。清除卡住的按键时
  如果用本帧的注入集合（`_padActions`）去判断，会踩一个很隐蔽的坑：这个集合在
  每个 `endFrame` 末尾就被清空了，等到「松开的那一帧」它早就是空的，循环一次都不进，
  按键永远删不掉。正确的做法是把集合在末尾滚到 `_padPrev`，下一帧拿它来判断。
- **「一次按压」不等于「一帧的按下沿」**。手柄只有每帧快照：一次物理按压横跨两帧，
  如果中间有一次 poll 但没走 `endFrame`（丢帧 / 切标签页 / 抛异常），
  同一次按压就会被算成两次。对暂停、建造这类**开关**动作，两次就是「开了又关」，
  表现成「有时候按了没反应」——而且极难复现。现在这些动作在
  `Input.injectAction` 里带 260ms 去重窗口（映射表里的 `toggle: true`）。
- **别用 .cmd / .vbs 装中文**。`wscript` 读 `.vbs` 用的是系统 ANSI 代码页，
  注释里的一个汉字就可能把后面那条语句吞掉（`shell.Run` 整行消失，快捷方式点了没反应）；
  批处理还受控制台代码页影响，连命令都解析不出来。
  启动器与快捷方式脚本因此全部改成纯 ASCII 包装 + Node 脚本
  （`tools/launch-hidden.vbs` / `tools/launch-game.cmd` / `tools/make-shortcut.mjs`）。
- **放大世界之前先量流场**。流场是整图 Dijkstra，代价随面积增长；
  304 格 + 逐格流场一次重算 20.7ms，每 0.45 秒一次就是肉眼可见的周期性卡顿。
  `tools/flowbench.mjs` 就是为这件事写的，现在靠 `FLOW_CELL = 2` 把它压到 3.7ms。
- **`import()` 一个模块会拿到「另一个单例」**。调试脚本里写
  `const { settings } = await import('/src/core/settings.js')`，
  浏览器会把它当成一次新的模块求值 —— 于是脚本改的是另一份 settings，
  游戏那边毫无反应，看起来完全像「改键功能坏了」。测试一律从
  `window.__frontier`（main.js 挂出来的**真实实例**）取，不要自己再 import。
- **`pressed()` 只在「按下的那一帧」为真**。游戏的渲染循环每帧都会 `endFrame()`，
  所以测试里「派发键盘事件 → 读 pressed()」中间可能已经跑过一帧，读到的永远是 false。
  稳的读法是按住状态（`input.keys` / `input.isDown`），或者显式用缓冲通道
  （`pressedBuffered`）。同样的道理适用于「一次按压被算成两次」的手柄场景。
- **波次要能自己收尾**。远程怪会风筝、卡住的怪会原地不动 ——
  只要有一只清不掉，波次就永远停在 `active`：下一波不来，整局卡死。
  现在有两条兜底：僵局检测（45 秒后连续 15 秒数量不降就把残兵拉到基地边）
  和超时收尾（240 秒后剩余虫潮撤退，按「未击退」结算）。
  测试里把 `run.waveTimeout` 调小，就不用真的等四分钟。
- **世界是随机的，测试不能依赖地形**。「采集要能采到」「载具要能开」这类用例
  如果直接用随机地图，会因为「最近的资源点恰好是不能采的虫卵囊」
  「载具恰好停在山壁前」而随机失败。现在：用例要么在开测前把地形整平/挑合法的目标，
  要么用固定种子重开一局（`restartRun(seed)`）。
- **`RNG.weighted` 的「取值字段」是约定，写错不会报错，只会静默返回包装对象**。
  它认 `e / value / v / t` 这几个键（见 `normalizeWeighted`），
  别的键一律当作「value 就是对象本身」。装备品质那段写的是
  `{ r, w: ... }` —— 于是 `rarity` 变成 `{r:'rare', w:22}`：
  查 `RARITY_DEF[rarity]` 得 `undefined`，拾取时读 `.name` 直接抛异常，
  而掉落本身「看起来是好的」（`item.rarity` 是真值，老断言只判真假就放过了）。
  同一个坑之前在 `director` 的怪物池踩过一次（表现为「一波怪都生不出来」）。
  **教训**：这类「返回值结构悄悄变了一层」的 bug，断言必须判**类型和取值范围**，
  不能只判真值 —— 现在烟测会掷 400 次并检查品质确实分布在高品上。
- **数据表里写了字段，不等于代码会用它**。旗舰残骸的
  `gearChance: 0.05 / gearRarity: 'relic'` 在 `PROP_DEF` 里躺了很久，
  但采集结算根本没读 —— 「撬残骸有 5% 出红装」这条设计其实是空的。
  加数据的时候顺手确认一下有没有消费方。
- **「面板能打开」不等于「面板能渲染」**。玩家在建造面板的「吸引装置」页
  撞到 `ReferenceError: TILE is not defined`（`panelBuild.js` 漏了一行 import）——
  而 `headless.cjs` 里「面板 openBuild 能打开」这条断言照样全绿，
  因为报错只在**切到那一页**时才发生。同一类还有三处：
  `actions.js` 的 `costText`（只在点装填/升级/维修时炸）、
  `panelInventory.js` 的 `scoreItem / itemWeight / SLOT_DEF`（空背包时看不出来，
  背包里一有东西就炸）、`run.playerStats.unlocks.meleeModules`
  （`unlocks` 其实挂在 `run.player` 上，playerStats 是 StatSet，只有数值 ——
  路径写错，装悬挂模块必定 TypeError）。
  **教训**：UI 测试要点到**每一页、每种数据状态**（空背包 / 有装备 / 有工坊 /
  没工坊），光验「面板打开了」等于没验。现在 `headless.cjs` 会把四个建造页签、
  三个科技分支、四个设置页签、殖民地的品质按钮全点一遍，并断言控制台零错误。
- **静态检查要成对**：`checkimports.mjs` 管「导入的名字存在吗」，
  `freescan.mjs` 管「用到的名字导入了吗」。两个都跑，上面那一类才拦得住。
- **绝对不要用 PowerShell 做「读文件 → 改 → 写回」**。`(Get-Content x -Raw)`
  在某次会话里按系统 ANSI（cp936）解码了 UTF-8 源码，`Set-Content` 再把乱码写回去：
  一个正则替换把 `src/data/tech.js` 里的中文与 emoji 全毁了，还顺手吃掉了
  160 行里每行末尾的字符和换行（GBK 一次吃两个字节，汉字三个字节，对齐就错位）。
  备份没有、git 也没有，只能整文件重建。
  **改源码只用 edit / write 工具**；非要用脚本，就用 Node（`fs.readFileSync(p, 'utf8')`），
  不要碰 PowerShell 的文本管道。
- **给核心数值加成长线时，先把上限想清楚，再在「读属性」的地方强制它**。
  武器的射程 / 伤害 / 射速 / 弹道由 `WEAPON_CAPS` 封顶（300% / 300% / 200% / 3 条），
  执行点在 `player.weaponStat()`，而不是「科技节点别超标就行」——
  科技、实验科技、装备词缀、红装特效会往同一个键上叠，只守一处是守不住的。
- **一个分支塞太多节点，图会被画到面板外面**。科技图按 tier 分列、列内竖向排，
  防御分支加上武器四条线之后最挤的一列有 8 个节点，而容器是 `overflowY: hidden`：
  最下面一排**看得见一点、点不到**。修法是给图区一个高度上限 + 双向滚动，
  并且把武器四条线单独拆成一个分支页（`BRANCH.WEAPON`）。
